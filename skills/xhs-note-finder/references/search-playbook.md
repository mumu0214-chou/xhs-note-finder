# 快速查找与适配筛选

## 先用产品资料决定查什么

在内部形成简短判断，不用先交一份营销报告：

- 买家为什么犹豫：价格、品质难辨、第一次怕不适合、使用麻烦、分量／规格难判断，或其他实际问题？
- 什么会让人主动想买：食欲或其他感官体验、地方口味、熟悉的生活场景、商家日常与人情味、合适的福利机会？这些方向与解决顾虑同样有效。
- 产品有什么已确认的差异，适合怎样的人、怎样的使用场景？
- 成稿默认沿用用户认可的商家口吻。参考来源以商家商品笔记为主，也可选消费者吃法、开箱或生活体验帖；注明原文叙述视角，不把消费者叙述当作商家自述。
- 要同品类、相邻行业还是跨行业？用户要求逐步跨行业时，先看购买问题相近的品类，再扩大，不一开始跳到很远的行业。

产品定位必须来自当次信息。未知的价格档位、工艺、特点不要凭空填；不必把所有疑问都问完才开始初筛。

用户明确说主打低价、品质或方便时，直接按这个方向开始搜索。未给定位时，查少量同细分、可比规格和到手价的商品，判断清楚再选方向；仍不清楚才问用户。价格必须相对合适的比较对象判断，不能跨等级、跨细分品类仅按每斤／每件金额判断。不要把一次任务的价格判断写成技能默认值。

## 用已认可的片段校准

按 [ledger.md](ledger.md) 找到共用的风格参照，从中挑与本轮目的接近的少量“原笔记片段＋认可稿片段＋反馈”配对，并看相关反例。了解哪些说话节奏、具体动作和产品转场得到认可，不只归纳成“自然、接地气”。

分别判断两件事：原文哪部分值得借；最终商家稿应有怎样的读感。用户认可改写稿，不代表原笔记整篇得到认可。原文口吻不同但结构值得迁移，仍可选并说明借用范围；不能要求每篇新笔记长得像旧稿。

参照中的产品、价格和人物经历只属于历史案例，不成为当前商品事实。只有明确反馈才记录认可；整理者对原因的分析要与用户原话分开。参照缺失时用当前聊天已有反馈，缺少原句就如实保留缺口，不编造历史好评或重构成“当时原稿”。

## 生成少量检索词，按结果调整

先挑 2—3 个有希望的方向，每个方向用自然的短词组合；不要把整篇产品说明塞进搜索框。

| 目标 | 可试的词形（只是候选，不要求全搜） |
| --- | --- |
| 学本行业商家怎么说话 | 品类名＋“我家／我爸／我妈／我们家的” |
| 解释偏高价格 | 品类或相邻品类＋“贵一点／为什么贵／用料／别只看价格” |
| 展示细分品类内的价格优势 | 品类或相邻品类＋“尝鲜／福利／这个价／先试试／到手” |
| 降低首次购买顾虑 | 相邻品类＋“先试试／第一次买／小份／小样／合不合适” |
| 学生活场景 | 使用场景＋“省事／一个人／下班／不用折腾” |
| 让规格可感知 | 相邻品类＋“到手多少／小包装／一套／怎么选” |
| 学经营者表达 | 品类＋“认识一下／跟大家说清楚／家里商量／有人爱吗” |
| 激发食欲或其他体验兴趣 | 品类＋“第一口／刚出锅／咬开／上身／用起来”，按品类选词 |
| 地方口味与家乡认同 | 品类或地方＋“本地人／这一口／在外地／家乡” |
| 商家日常与招呼 | 品类＋“今天店里／跟大家聊聊／认识一下／来尝尝” |

从品类词入手认识行业语言，再用购买兴趣、顾虑和说话方式扩展，不要一直只换商品名。以上是可选方向，不要求每批覆盖，也不把“我爸／我妈”当作自然口吻的必要条件。低价福利本身不是淘汰理由：目标商品在其细分市场有价格优势时，应主动搜这一类。只有原文依赖目标商品做不到的优惠、条件或叙事事实，才排除相应部分。结果重复或不适配时，换兴趣／顾虑／场景词。

进入用户指定的平台或来源；使用千帆等商业内容入口时，可在页面实际可用的商品相关内容中查找。栏目和筛选项以当前页面为准，不硬编码按钮、接口或排序规则。

## 分两轮阅读，控制无效打开

选 3 篇时，可先浏览约 20—30 条候选的标题、封面和可见简介，再精读约 6—10 篇有希望的正文。这是工作量参考，不是必须凑满的数字；稀少主题可以扩大，有好结果可以提前停。

粗筛先排除：与目标兴趣或顾虑无关、标题吸引但没有可迁移话题、重复搬运、明显依赖目标商品不存在的优惠／身份／工艺、仅靠画面而拿不到所需内容的候选。

精读时记录：

1. 开头让读者为什么愿意继续看？
2. 正在聊的事情和情绪是什么？
3. 哪一句自然引出商品？
4. 购买理由能不能由目标商品的真实事实支持？
5. 结尾怎样引导尝试？

顺手记录 URL／ID、阅读范围和内容摘要，后面不要为了同一字段再开一遍页面。批量提取已显示页面内容应按浏览器工具允许的方式进行，不另造无授权抓取途径。

## 选得准：硬条件先过，再比较

入选参考应满足：正文实际可读；借用部分与目标兴趣或顾虑相关；吸引力能迁移；不需要虚构事实才成立。无需每篇都有科普或明确反驳，能把具体体验写得让人想试也可以。完整读过后，即使只有标题、开头或转场值得学，其他部分写得普通，也可以入选，但说清楚只借哪一部分，不把整篇都称为优秀。

在合格候选间优先挑：

- 叙述自然，像在聊具体事情，产品转场顺或可自然转成商家表达；
- 开头、展开或收尾有值得借的具体做法；
- 改到目标商品时所需改动合理，不会把原文吸引力全部拆掉；
- 同组笔记覆盖不同表达结构或购买问题。

不要单看点赞、收藏、评论。数据可辅助了解关注度，但不能推导销量；发布时间、作者体量、付费分发等未知时，不硬算“爆款率”。账号身份也须标明可见经营线索或推断，不把显示名当身份验证。

三篇通常不选同一账号的三篇近似稿，也不全选“和爸妈商量后”。用户专门研究某个结构或账号时例外。

消费者体验帖可以借场景、动作顺序和感受表达，转成商家的吃法／用法建议或产品介绍。原作者的购买、回购、亲友评价和个人经历不能变成商家已有事实；若去掉这些经历后就失去吸引力，而当前产品又无承接点，则不选。

## 把迁移理由说具体

每篇用短片段和几句话解释，不写成营销分析报告：借哪里、为什么有用、当前产品怎样接。原文摘录保持短且准确，概括不要冒充原句；对照当前已知资料说明承接点，事实缺失时标条件，不能先假设商品具有某个卖点。

例如，仅在当前商品确有小份规格时，可说明：“借商家劝顾客先少买一点的开头。它让第一次尝试显得轻松，你的小份规格能承接；原文的赠品活动不适用。”这是选择理由，不是新文案。

选消费者场景帖时，可说明：“借先讲具体麻烦、再用一个动作解决的顺序。当前商品若确实省去该步骤，可转成商家的使用建议；原作者的购买经历不带入。”实际交付时用该商品已知的动作和特点替换泛称，不能照抄这句空泛说明。

## 探索新写法，复查旧模板

默认找 3 篇，争取 2 篇台账中还没有的新写法，1 篇已认可模板的近期新样本。其他数量大致沿用约三分之二探索的倾向，不用机械凑整；用户指定某类或从旧库挑时按用户要求。

模板按“开头的作用—激发的兴趣或解决的顾虑—产品转场—收尾方式”辨别。换商品、换作者、换同义词，结构基本相同，仍是同类模板。不要为凑新模板数量故意细分名称；可以记录同一模板的新变式。

已用过的原笔记默认不重复交付；认可过模板的另一篇新笔记可以交付，但仍检查本批内部重复。新写法不够好时如实说明短缺，不拿不适合的稿凑比例。

台账记录最近采用时间、采用次数、用户反馈、近期是否发现值得参考的新样本。每次查找重新判断，不设永久“优秀”，也不按固定天数一刀切淘汰：

- 用户开始觉得重复、不想用：记录原话，降低推荐优先级。
- 实际搜索后没有找到适配的新样本：记录本轮搜索范围与结果，标“待复查／降低优先级”，不夸大成整个市场都已失效。
- 未进行近期搜索：只记“近期情况未知”，不把没查当作过期。
- 后来找到合适新样本或用户重新采用：可重新启用，保留变化理由。

“认可”表示用户愿意采用这种文案，不是已验证成交。若用户提供发布效果，单独记录实际指标、时间范围及来源，再用于判断。裂变 10 个版本不计成模板被独立采用 10 次。

## 什么时候停止

找到所需数量、正文可读、适配理由明确且组合有区别时停止，不为了多搜而多搜。

若一轮结果明显不合适，换一个检索维度；多轮仍不够时交付已找到的合适结果并说明具体缺口。不要承诺固定用时或“必定爆款”，也不要把登录等待计成阅读样本。

## 样本复用

每次先读共用台账，再检索当前聊天／当前项目已知样本，用于判断风格和排除已交付、已用原文。默认交付新的可用参考；“新”指未交付且值得新增，不一定必须刚发布，若声称“近期新样本”则须核对发布时间。用户明确说从旧库挑时，才以历史样本复用为主，注明来源。

同一来源只保存一次基本记录，新的选择理由可按任务附加。索引与原文留在项目资料，不塞进技能文件；写作阶段通过 reference_id 和路径读取，不把完整来源重新发给用户一遍。
