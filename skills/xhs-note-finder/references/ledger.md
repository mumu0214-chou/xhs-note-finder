# 共用笔记台账

台账独立于技能和单个产品，所有产品／项目共用。默认位置：`~/Documents/Codex/小红书笔记台账`。技能中不写具体产品资料；台账只按任务需要记录产品标识、来源和使用反馈。

技能自带的 [style-baseline.md](style-baseline.md) 提供可迁移的基础口吻，外部风格资料和动态台账是补充。新设备没有台账时，`show` 返回空记录，首次 `merge` 自动建立台账，不影响先找笔记或写作。要延续哪些原文已经用过等历史，才需要迁移旧台账；不要把没有旧记录说成必须重新训练风格。

## 文件与操作

- `ledger.json`：笔记、模板与使用记录的唯一可编辑数据来源。
- `笔记台账.md`：由脚本生成的可读视图；不要手工编辑，以免与数据不一致。
- `ledger.json.bak`：最近一次写入前的备份。
- `风格参照.md`：单独维护的语言参照，保存少量原笔记／认可稿片段配对和反例；不由台账脚本重建。按当前任务读取相关部分，原文和反馈证据保留可查位置，不复制到技能里。
- `风格参照证据.json`（有历史原句可保存时）：参照所用稿件、反馈和消息位置。只保存实际取回的内容，不根据摘要补写原稿。

本技能附有 `scripts/ledger.py`，仅用 Python 标准库。先用 `show` 阅读；更新时准备 JSON 增量文件，用 `merge` 合并；合并会校验引用并重建视图。可用 `--root` 指定其他路径，但不要在不同项目悄悄创建互不关联的新台账。

在本技能目录运行（输入文件用实际路径）：

```sh
python3 scripts/ledger.py show
python3 scripts/ledger.py merge --input /absolute/path/update.json
```

脚本位置随技能安装目录调整。不要重建或覆盖已有台账来回避冲突；相同 ID 递归合并，列表按传入值替换，事件按 ID 去重。

## 数据层次

顶层有 `sources`、`templates`、`products`、`uses` 四个以 ID 为键的字典，以及 `events` 数组。来源 ID 尽量用真实笔记 ID；同一原文去除不同追踪参数后仍只记一份。

- `sources`：原文标题、URL、作者、行业、阅读范围、正文／正文位置、发现与读取时间、首次交付时间。
- 本轮选中来源还应保留叙述视角、值得借的片段、吸引点、当前产品承接点和必要的视角转换；不同产品的适配说明放在对应使用记录或带产品标识的选择事件中，避免覆盖成全局结论。
- `templates`：名称、结构特征、最近观察到新样本的时间、最近复查时间、复查结论及理由。结论使用“新候选／认可过待复查／本轮适用／降低优先级”等动态状态，不使用永久优秀标签。
- `products`：产品标识及名称；没有必要就不存完整商品资料。
- `uses`：每次具体使用，关联 source_id、template_id、product_id，记录项目、改写状态、裂变数量、反馈、作品位置、发布情况。相同原文用于不同产品是不同使用记录。
- `events`：实际动作或明确反馈的日期、证据、涉及对象；历史补录标明日期精度及来自聊天，不伪造精确时间。

使用记录核心字段示例（元语法，不含固定产品数据）：

```text
id / source_id / template_id / product_id / project
rewrite: {status: pending|done, completed_at, title, output_location}
variants: {status: pending|done, count, completed_at, output_location}
feedback: {status: unknown|approved|rejected|revise, date, quote, target}
publication: {status: unknown|published, evidence}
```

反馈 target 区分参考选择、母稿、裂变组或模板，不把对一组裂变的认可扩成所有原文都被认可。不同阶段反馈可追加事件保留。

风格参照同样区分用户原话与整理者分析。认可稿可以用于理解用户偏好，不能据此标原文全篇优秀；曾被否定的表达保留上下文和具体问题，不把某个词永久禁用。新增偏好与旧偏好冲突时记录变化及适用范围。

## 谁记录什么

- 查找技能记录发现、阅读、交付、模板判断；读取使用记录，排除已用原文、决定探索方向。
- 已改写：有完成稿才记 done；已裂变：实际交付几篇才记几篇。仅选中参考不算使用。
- 用户明确说“不错、就这样、采用”等，可记录认可并关联对应对象；没有反对不算认可。
- 发布状态必须有明确记录，否则保持 unknown。改写完不等于发布。
- 生成多少裂变版本与模板采用几次分开统计；一份母稿裂变十篇，仍是一条母稿使用记录。

本轮只实现查找技能与台账。写作技能尚未接入自动回写；历史状态可依据当前聊天证据补录，未来自动回写需另行联调。不要声称已具备跨技能自动追踪。

历史稿如果只存在聊天中，output_location 如实写聊天批次与标题，不伪造文件路径。新任务若保存正文，记录实际文件路径。查找技能不负责重写或补生成历史稿。
