# 小红书对标笔记查找

目标：让 AI 实际使用浏览器或已有样本，找到值得借鉴、能迁移到目标产品的真实笔记。不是让用户代找，也不是仅列搜索建议。

## 边界与输入

- 输入当次产品资料、希望激发的购买兴趣或解决的顾虑、所需数量和参考范围。已有信息从当前聊天或指定资料读取；不在技能中保存固定产品档案，不把缺失的产品事实当作已知。
- 用户只说“找几篇”时，默认先选 3 篇；用户数量、品类范围和平台要求优先。若连目标产品／目标话题都无法判断，只问最关键的缺项，不重新问已明确的信息。
- 本技能只查找、筛选和解释适配理由，不改写标题正文，不裂变，不发布。
- 写作由独立技能 `xhs-product-copy` 负责。用户只要求查找时，交付选中结果后结束；明确要求“找并改写”时，完成交接后顺序使用写作技能，不额外要求用户重复确认。

## 执行

开始查找前阅读 [search-playbook.md](references/search-playbook.md) 和 [ledger.md](references/ledger.md)，按检索、筛选和台账流程执行。不要因浏览器能搜索，就跳过产品适配分析。

1. 从产品资料识别购买兴趣、使用场景或购买顾虑，同时考虑体验、地方特色、商家日常、福利等表达方向，不固定为低价、科普或避坑。用户已给定位时按该定位开始；没给时可查少量同细分、可比规格与到手价的商品，不用绝对金额判定便宜或贵。
2. 先读 [style-baseline.md](references/style-baseline.md) 校准口吻，再读取可用的共用台账；本机风格资料作为补充。历史目录不存在也可用随包参照工作，从空台账开始，不要求用户重新教口吻。识别已经交付／用过的原笔记和模板类型，默认找尚未交付、值得新增的参考；已交付原文只作备选，不占新增篇数。用户明确从旧库挑时才以复用为主。
3. 需要浏览时优先使用可用的 ego-browser 技能，先按其说明取得当前浏览器指南。用户已指定身份时沿用；不在技能中固定账号或 TaskSpace，也不擅自翻查无关账号／目录。
4. 先粗筛，再读取少量有希望的正文。关键词或结果明显不合适时换检索方向，不机械翻页。快速不等于只看标题。
5. 以商家商品笔记为主，允许消费者体验帖入选；注明原文叙述视角，以及怎样转成商家表达。先保证适合迁移，再参考互动等可见数据，不设统一点赞门槛。低价福利也是候选方向，只要目标产品在相应细分市场确有价格优势且条件相符；完整读过的笔记只有一部分好用，也可以注明借用范围后选入。
6. 默认找 3 篇时，争取 2 篇属于台账没有的新写法，1 篇属于认可过模板的近期新样本。空台账或没有适用的认可模板时，可全部探索，不虚构历史使用记录。新笔记不等于新模板；不为凑比例选差稿。已认可模板每次重新判断，不永久标记优秀；详见参考文档。
7. 保留可复用的来源与阅读记录，按下方格式交接并更新台账。不要重复阅读已经有可靠完整记录的同一内容。

## 阅读与计数的真实性

- 默认交付完整正文已读的参考笔记。标题／封面参考可作为单独标明的补充，不冒充完整正文样本。
- 视频若只读到简介，必须标明“仅读文字简介”，不声称听过口播；任务需要口播时，只有取得并阅读对应转录后才计入。
- 登录拦截按浏览器技能交接给用户；可继续分析已有可读样本，不绕过访问限制。
- 笔记 URL／ID 去重；相同账号的近似改写还要按内容去重。同名作者不等于同一账号。
- 没有找到足够合适、可读的结果时，如实报数量及缺口，不用无关笔记凑数。普通查找不自动扩成几百篇研究。

## 交付与交接

给用户每篇展示：标题及直达原文链接、作者（可见时）、原行业与叙述视角、阅读范围，再用几句口语说明“值得借的短片段 → 原文为什么吸引人 → 当前产品能接在哪里”。必要时点明不能照搬的部分；消费者体验帖还须说明商家视角的转法。不要只写“爆款、互动高、可以借鉴”，也不在这一步输出目标产品的改写稿。具体示例见 [search-playbook.md](references/search-playbook.md)。

每次按 ledger.md 用 start/select 保存任务及以下资料，生成共用台账中的 handoffs/<task_id>.json；交给写作技能时给出绝对路径和 task_id/use_id，不只依靠当前上下文：

```text
reference_id / 原始笔记 URL 或 ID
title / 可见作者及主页 URL（如有）/ 来源行业
source_voice: merchant | consumer | unclear，依据可见叙述判断，不等于账号身份认证
query / 发现渠道 / 读取日期
reading_scope: full_text | caption_only | title_cover_only
source_text: 实际已读正文或简介，内部供写作使用；不必在最终回复重复贴全文
pattern: 开头 → 正在聊的事 → 产品转场 → 收尾
borrowed_excerpt / excerpt_location: 值得借的短片段及其所在位置；摘录与概括分清
attraction: 这段表达怎样激发兴趣或回应顾虑
product_bridge: 当前产品的哪个已知特点、规格或场景能承接，保留了什么吸引力
role_conversion: 消费者体验如何转成商家表达（若适用）
transferable: 可借的表达方式
non_transferable: 原文独有、不能直接套入目标商品的事实
template_id / 本轮属于新模板还是已认可模板的新样本
reused_parts / 只借原文哪一部分（若适用）
```

只保留本次可访问、授权范围内的内容；用户输出以链接、简短摘要和原创分析为主。已保存样本放在项目工作资料中，不嵌进技能、不固定产品或个人账号信息。

## 台账闭环

开始先运行 `scripts/ledger.py show` 和 `query`；沿用同一任务的编号，不为重试另开记录。按 [ledger.md](references/ledger.md) 记录实际选中的来源、产品适配和模板观察，完整正文与事实快照随交接文件保存。只找任务记录 finish；找并写任务由写作技能完成后 finish。结束前读回确认成功，写入失败如实说明。

收到明确选择／模板反馈时限定对象记录；改写或裂变状态由实际稿件决定，不因选中而推断完成。默认去重已交付原文；旧模板的新来源仍须重新审视适配度，反馈、发布和成交不能混算。

运行台账时按 ledger.md 选择本机 Python 命令与路径：Windows 可用 `py -3`／`python`，macOS/Linux 通常用 `python3`。共用目录不存在时首次记录自动建立，不把其他电脑的绝对路径照搬过来。
